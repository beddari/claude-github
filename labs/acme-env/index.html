acme-env

Split DNS and an internal certificate authority for local clusters, as four containers in podman. A zone, lab.test, that anything can publish names in, and an ACME CA that issues certificates for them: per name over HTTP-01, the wildcard over DNS-01, and a CA of its own for each cluster.

Why

A cluster on a laptop needs names that resolve and certificates that verify, without a public domain or a public CA. acme-env gives it both through the same protocols it would use in production: external-dns writes records, cert-manager speaks ACME. Names outside the zone resolve as before, and nothing goes in /etc/hosts.

What you get

serviceportwhat it does
CoreDNS1053Answers for lab.test from etcd, and forwards every other name
etcd23790Holds the records; external-dns and task acme-env:record-add write them
step-ca8443The ACME CA, "Lab Internal CA": 24-hour certificates under a root you trust once
BIND1054Takes DNS-01 tokens as RFC 2136 updates signed with the TSIG key lab-dns01

All four use the host network, on the address of your default route or HOST_IP. task acme-env:cluster-ca signs a CA for a cluster with the root, as talos-cluster does for its Kubernetes CA.

What the test prints

task acme-env:check gets two certificates with lego and verifies each against the root; both together took 5.4 seconds on a Linux host: 

$ task acme-env:check
>>> Getting a certificate for smoke.lab.test over HTTP-01 ...
INFO  The server validated our request. domain=smoke.lab.test
X.509v3 TLS Certificate (ECDSA P-256) [Serial: 5877...0252]
  Subject:     smoke.lab.test
  Issuer:      Lab Internal CA Intermediate CA
>>> Getting a certificate for *.lab.test over DNS-01 ...
INFO  The server validated our request. domain=*.lab.test
X.509v3 TLS Certificate (ECDSA P-256) [Serial: 1851...5765]
  Subject:     *.lab.test
  Issuer:      Lab Internal CA Intermediate CA
>>> All good: step-ca issued smoke.lab.test over HTTP-01, *.lab.test over DNS-01.

Plug it in

You need podman, Task and dig; brew bundle installs them from the repository's Brewfile, on macOS and Linux. 

git clone https://github.com/beddari/claude-github && cd claude-github
brew bundle
task acme-env:up        # about 5 seconds
task acme-env:check     # binds port 80: rootful podman, PODMAN="sudo podman"
task acme-env:trust     # trust the root on this computer

Use it

# a name in the zone
task acme-env:record-add -- myapp 192.0.2.2
task acme-env:dig -- myapp

# any ACME client: the directory, and the root to trust
https://192.0.2.2:8443/acme/acme/directory
labs/acme-env/.run/root_ca.crt

# a CA for a cluster, signed by the root
task acme-env:cluster-ca -- mycluster /path/to/dir

Use your host address in place of 192.0.2.2. Not tested: macOS, where podman runs in a VM, and rootless podman for the HTTP-01 test.
