talos-cluster

A small Talos Kubernetes cluster in Docker that plugs into acme-env. Its Kubernetes CA is signed by acme-env's root, external-dns publishes its Ingresses in the lab zone, and cert-manager gets their certificates over ACME, a wildcard included.

Why

To try an app the way it runs in a real cluster: a name that resolves, HTTPS that verifies, and certificates that renew, all from one Ingress. One command builds the cluster and ends with a test of the whole chain, so a change to a chart, an image or acme-env shows up as a failing step.

What you get

partwhat it does
Talos v1.14Kubernetes 1.37: a control plane at 10.5.0.2 and a worker at 10.5.0.3, in Docker
cluster CA"acme-lab Kubernetes CA", signed by acme-env's root; the API server's certificate chains to it
TraefikThe ingress controller, on the worker's ports 80 and 443
external-dnsWrites the names of Ingresses into acme-env's etcd
cert-managerThe issuer step-ca: HTTP-01 for names, DNS-01 for *.lab.test
whoami, helloDemos at https://whoami.lab.test and, on the wildcard, https://hello.lab.test

Plug it in

You need Docker, talosctl, kubectl, helm, jq, curl and dig, from the repository's Brewfile, and acme-env up. The two nodes take 2 CPUs and 2 GiB each. On Linux, load br_netfilter first. 

git clone https://github.com/beddari/claude-github && cd claude-github
brew bundle
sudo modprobe br_netfilter
task acme-env:up
task talos-cluster:up       # about 3.5 minutes; ends with verify
export KUBECONFIG=$PWD/labs/talos-cluster/.run/kubeconfig

Use it

Any Ingress in the zone gets a record and a certificate: a host in lab.test, the class traefik, a TLS secret and the issuer. 

metadata:
  annotations:
    cert-manager.io/cluster-issuer: step-ca
spec:
  ingressClassName: traefik
  tls:
    - hosts: [myapp.lab.test]
      secretName: myapp-tls
  rules:
    - host: myapp.lab.test

Not tested: macOS, arm64, more than one worker, rotating the cluster's CA, and upgrades in a running cluster; task talos-cluster:down and up is the tested way.
