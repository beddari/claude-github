skill-audit

A single Go binary that checks your Claude skills (folders with a SKILL.md) against Anthropic's updated skill-authoring guidance. It reports what's off and can write the prompt that asks Claude to fix it, plan first.

Why

Skills written early on followed the original advice: a good description, a short SKILL.md, references split out. The guidance has since grown. Claude previews long reference files with head -100, so anything important below line 100 with no contents list may never be read. References nested two levels deep only get partially read. Risky steps belong in scripts, not prose. Most of the fixes are about how the files are laid out and which checks they run, not the wording, which makes them something a tool can find.

What it checks

checkrule
frontmatterValid name, plus a third-person description that says when to use the skill
lengthSKILL.md body under 500 lines; it's the contents page for everything else
contentsReference files over 100 lines start with a contents list that matches their headings
nestingEvery reference is linked directly from SKILL.md (one level deep); flags orphans
linksLocal links resolve
freedomRisky steps (money, deleting, migrations, deploys) use an exact script, not loose prose
modelsThe models the skill was tested on are recorded in the frontmatter
emphasisNot shouting ALL-CAPS MUST/NEVER/IMPORTANT, which newer models handle worse
checklistOrdered workflows give Claude a - [ ] checklist to copy and tick off
feedbackValidation steps loop: check, fix, repeat until it passes
depsEvery package and CLI tool has an install line next to where it's used

The checks are pattern-based. Testing on Haiku, Sonnet and Opus, and deciding how much freedom each step gets, can't be automated, so the generated prompt lists them for manual review.

What it found on real skills

The first run covered 13 skills installed in a Claude Code cloud session. None of them recorded tested models. A few findings stood out:

  • pdf uses 17 packages and tools (pypdf, pdfplumber, poppler…) but has install lines for only two.
  • skill-creator has four reference files over 100 lines with no contents list, and its SKILL.md is close to the 500-line limit.
  • docx and xlsx ship a validator script but never say to fix the errors and validate again.

Get it

linux / amd64 linux / arm64 macOS / Apple silicon macOS / Intel windows / amd64

Each download is built from main on every publish (checksums in SHA256SUMS). On macOS, run xattr -d com.apple.quarantine skill-audit-darwin-* and chmod +x it first. You can also build it yourself: 

go install github.com/beddari/claude-github/tools/skill-audit@main
# or, from a clone:
task skill-audit:install

Use it

# audit ~/.claude/skills and ./.claude/skills
skill-audit

# specific folders, a single skill, or one SKILL.md
skill-audit ~/work/plugins/skills ./my-skill

# a prompt for Claude: confirm each finding, show a plan, then fix
skill-audit -prompt > fix.md
skill-audit -prompt-dir prompts/      # one prompt per skill

# in CI: exit 1 on any fail
skill-audit -strict -format json
